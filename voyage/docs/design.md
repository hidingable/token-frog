# Voyage 产品设计

Voyage（占位名）是一个独立的 macOS 原生养成游戏，同时也是一个看得懂的 AI 用量工具。你把一只小信使从蛋养大，它靠你工作用掉的 token 走遍世界、写信回家，把一间破旧的小邮局慢慢变成世界邮局。

**工作决定它走多远，陪伴决定它变成谁。**

- 全部界面：[mockup.html](mockup.html)
- 技术方案：[technical.md](technical.md)

## 产品定位

| 问题 | 回答 |
|---|---|
| 给谁用 | 每天使用多个 AI 编程工具的 macOS 用户 |
| 解决什么 | token 和额度很抽象；现有工具只有图表，没有打开它的理由 |
| 为什么每天打开 | 想看它今天写了什么，想看它有没有照你说的做 |
| 和用量工具的区别 | 数据完整，但有一只你养的宠物和持续更新的故事 |
| 和宠物游戏的区别 | 它的旅程由你真实的工作驱动，不需要额外操作 |

产品不依赖 Token Monitor，只在实现思路上参考它。用量来自本机的 tokscale，额度来自用户自己关联的账号。

### 设计目标

- 每天有一个想打开的理由，而且只花 2 分钟。
- 你说的话几封信内就能看到结果。
- 宠物越养越不可替代：它记得你们的事，这段历史换不走。
- 不打开图表也能感知今天走了多远；额度等细节都放在数据面板里。
- 什么都不操作，旅程也照常推进。
- 粘性来自期待和感情，绝不来自多烧 token 或害怕失去。

## 已确认的决定

这些已经定了，实现时不用再讨论。

| 主题 | 决定 |

| 邮友介绍 | 先从内置内容随机，不做用户标签总结 |
| 奖励 | 永不与 token 用量正相关 |

## 信息架构

### 常驻形态

| 形态 | 内容 |
|---|---|
| 刘海 | 收起：宠物、进度、目的地、新信数。悬停展开：地图、今日里程和总量、当天的途中线索 |
| 小浮窗 | 可拖动的宠物和今日里程。单击有反应，双击打开主窗口 |
| 菜单栏 | 打开主窗口、刷新、开关形态、退出 |
| 通知 | 早间来信，每天最多一条 |
| 小部件 | 明信片相框（M4）|

### 主窗口

一级导航只有五项，设置放在右上角。

| 一级 | 二级 | 说明 |
|---|---|---|
| **邮局** | 无 | 首页，每天从这里开始 |
| **旅途** | 无 | 地图、路线、下一站、途中线索、我的足迹 |
| **信箱** | 全部、旅行信、明信片、长信 | 有新信时显示红点 |
| **收藏** | 护照、行囊、纪念品、菜单、邮友、记忆簿 | 所有长期积累 |
| **数据** | 看板、额度 | 工具部分，不做游戏化 |

宠物的档案从邮局点宠物打开，关联账号从额度页和设置打开。未上线的邮友等二级页先隐藏。信箱显示全部、旅行信、明信片、长信；收藏显示记忆簿。

## 核心规则

### 两条轨道

| | 里程 | 陪伴 |
|---|---|---|
| 来源 | token | 打开、看信、回应、带工具 |
| 决定 | 它在哪、去过哪、护照 | 形态、习惯、记忆、小邮局 |
| 用得多 | 走得远，盖章多 | **没有任何加成** |
| 不操作 | 照常前进 | 不变，回来接着养 |

**硬性规则：同一天用量翻倍，习惯、掉落、形态和故事进度都不变。** 这条写成测试。

测试固定这些结果：习惯数值、形态、陪伴日、周章、信的数量、掉落稀有度和保底、回应兑现的时机。用量决定它走到哪，所以到达的城市，以及由城市决定的当地故事和当地东西可以不同。

### 里程

**1 万 token = 1 公里。** 绕地球一圈（约 40,075 公里）约 4 亿 token，系数固定不变。

里程燃料 = 未缓存输入 + 输出 + 缓存写入。缓存读取和推理不计入，否则距离会被缓存读取淹没。总量和里程是两个数，界面始终分开标注。

### 底线

- 没有死亡，没有离家出走，收集品和记忆永不丢失。
- 不清零、不扣分，通知不写内疚文案。
- 通知每天最多一条，且只在真有信时发。
- 节日内容可以限时，但明年会回来。
- 不接入付费、排行榜或比拼用量的社交。
- 奖励永不与 token 用量正相关；用量不发券，也不提高任何概率。
- 不设饥饿值。它会用气泡表达想听回应、想带工具，但不满足也不会变糟。

## 体验循环

### 工作时（0 秒）

宠物和工作同步：干活时赶路，闲下来打盹，快到站时显示“还差 12 km”。每天最多寄一条[途中线索](#途中线索)，比如“我找到一把屋顶那么大的扇子”。线索只在旅途页和悬停后的刘海展开区静默显示，不自动展开、不弹窗、不发通知；首次到达新国家仍按已有通知开关处理。

### 途中线索

- 当天有计入里程的用量才可能有。是否寄来、选哪一句只由旅程种子和本地日期决定，不读取用量大小、扫描次数、当前城市或打开时间；开始工作后即可出现，不必等日结。零用量时不作永久决定，之后有用量再判断。
- 每天首次有用量时保存抽取结果，未抽中也保存。选中的 ID、内容版本和完整中英文原文保存在当天记录，重复扫描、重启、跨天补算和更新内容包都不重抽、不改写。当日以外的线索仍留在存档，当天的展示不借用昨天的线索。
- 旧存档从升级当天开始启用，不补发升级之前的线索；启用以后漏扫的日期按最终用量补算，与逐日扫描结果一致。
- 文案来自 `Content/road-clues.json`，都是原创的小发现或想象，不陈述未经核实的现实知识；中英文完整并通过内容校验。
- 途中线索不是信，不占信件编号、没有奖励，也不推进保底、兑现、习惯、陪伴日或周章。它与纪念品重复所得的“旅行线索 / trailClues”互不转换，不解锁重游。

### 每天（2 分钟）

每晚它搭夜航邮班回到邮局，第二天 09:00 把信交给你。这只是表现，不影响里程；你开始工作，它就回到路上。

1. **收信：** 它叼着信趴在刘海上，邮政红角标留到拆开为止。
2. **看信：** 信、照片和行程单。东西自动带回家。
3. **回应一句：** 写入记忆簿并影响习惯，也可以留着以后再说。
4. **带一样东西：** 从行囊里选，不选就随机带一样。下一站由它自己决定，你只能通过心愿影响方向。

信的结尾留一个钩子，让人想看明天的信。

### 每周

每个陪伴日盖一个早安章，与用量无关；周一开始新的一周，章数重新计，但不算失败。

- **4 章：** 周礼盒。
- **6 章：** 礼盒多一件。
- **本周心愿：** 玩家自己写一句话，比如“想去一个靠海的城市”，见下面的规则。
- **周日长信：** 本周里程、工具、趋势和一件大事回顾。

### 长期

- **修复邮路：** 每个大洲一段断掉的邮路，分章连载，修好后邮局扩建一间。
- **形态和身份：** 见下一节。
- **记忆日：** 第 100 天、到某地满一年、“去年今天你在……”。

### 第一次打开

前 5 分钟决定用户是否留下。这时读取最近 30 天的用量，但**不计入里程**。

1. 选一颗蛋，对应四个角色。
2. 选家乡邮局，也就是旅程起点，默认上海。
3. 孵化，给它起名。
4. 收到航海日志信：工作日几点开工，周末是否打扰你，谁是你的老伙计。全部来自真实数据。
5. 它随机挑出第一站。你从初始行囊里选一样东西，不选就随机带一样，然后出发。告诉你明早 9 点会有信。

### 新内容如何出现

| 时间 | 新东西 |
|---|---|
| 第 1 天 | 孵化、起名、航海日志信 |
| 第 2 天 | 第一封旅行信，第一次回应，记忆簿开始 |
| 第 3 天 | 习惯第一次兑现：它做了你说过的事 |
| 第 7 天 | 幼年形态，第一个周礼盒 |
| 第 14 天 | 第一次奇遇，第一位邮友登场 |
| 第 30 天 | 少年形态，邮局可布置，第一段邮路连载 |
| 第 100 天 | 旅人身份，100 天纪念信 |

### 不在的时候

离开 3 天以上，它继续旅行，信积攒起来。回来时收到一封重逢信和一件重逢礼。**回来永远是好事，而不是清算。**

离开只比较主窗口两次实际打开的本地日期：相差至少 3 个自然日即触发（例如 11 月 1 日打开，11 月 4 日再打开）。后台运行、用量、扫描、浮窗和刘海不算打开；打开任意主窗口页面都刷新这个日期，不要求拆信。同一天只判断一次。旧存档升级后的第一次打开只建立基线，不推断以前的离开，也不补发历史重逢信。

## 养成

玩家看不到点数、等级或每日任务。变化都落在它的行为、外形和家里。

### 习惯

首版有两种习惯：**爱搭话**和**爱观察**，可以并存，也会慢慢变。

- **怎么变：** 回应和工具都带倾向，比如“下回进去问问”加强爱搭话。
- **怎么兑现：** 第一次回应后，下一封有资料的信必须出现由此引起的行为。
- **怎么留下：** 在泉州学会把油条一半泡汤、一半留脆，回家以后还这样吃。
- **长期结果：** 到旅人形态获得身份，见下面的身份表。

### 形态

**陪伴日**是你打开并看过信或明信片的一天，与用量无关。没打开不扣分，也不用补。仅打开主窗口或写出信件不记陪伴日；读到时记阅读当天，同一天只记一次。

| 形态 | 陪伴日 | 按每周约 5.8 天 | 变化 |
|---|---|---|---|
| 蛋 | 0 | 第一次打开 | 孵化，起名 |
| 雏 | 1 | 当天 | 开始旅行和写信 |
| 幼年 | 5 | 约 1 周 | 身体变大 |
| 少年 | 20 | 约 1 个月 | 邮路连载，邮局可布置 |
| 旅人 | 60 | 约 3 个月 | 由习惯决定身份 |
| 老练 | 170 | 约 7 个月 | 能带回邮友 |
| 传奇 | 340 | 约 1 年多 | 邮局升为世界邮局，开启第二段邮路 |

### 身份

先内置六种，到旅人形态时按实际经历决定。多个条件接近时随机选一个，之后还可能随经历改变。

| 身份 | 依据 | 外观 |
|---|---|---|
| 联络员 | 爱搭话最强 | 挂铃铛的邮包 |
| 速写家 | 爱观察最强 | 羽毛笔和画夹 |
| 美食家 | 手绘菜单最多 | 小围裙 |
| 收藏家 | 纪念品最多 | 大背包 |
| 探路者 | 到过的国家最多 | 地图筒 |
| 老街坊 | 熟客城市最多 | 旧围巾 |

### 行囊

行囊就是玩家的仓库：**你现在有什么，出门时才能带什么。**

- **初始：** 第一次打开时有三样：速写本、问路条、雨衣。
- **获得：** 周礼盒和少数稀有际遇会增加新东西。
- **携带：** 每天带一样，不选就从行囊随机带一样。东西不消耗，回来后还在。
- **作用：** 影响到站后发生的事，不影响距离，也不是出行的前提。

| 东西 | 可能引出的事 |
|---|---|
| 速写本 | 找角度画下一张可以带回家的画 |
| 问路条 | 找摊主或手艺人搭话，问到配方或说法 |
| 雨衣 | 当地的雨季才会触发的雨中故事 |
| 老相机（礼盒）| 拍下一张可以贴进记忆簿的照片 |
| 空饭盒（礼盒）| 把当地的吃法学回家 |

### 本周心愿

玩家可以写一句话，每周一句，也可以不写或清空。它影响下一次抽站和旅途情节的偏向，不保证结果；已经抽好的下一站不改变。每周一按用户本地时间自动清空，不算失败。

1. **解析：** 先按当前语言的内容关键词匹配统一标签，比如“靠海”对应 `coast`；有本机模型时再补选已有标签，非法标签丢弃。模型不可用、超时或失败时只用关键词结果。文字不上传，也不消耗云端 token。
2. **能关联：** 下一站和故事优先选符合标签的。
3. **关联不到：** 就随机，下一封旅行信里会说“没太听懂，我先随便走走”。同一条心愿只说明一次，双语文案随信保存。

无论写什么，都不改变稀有度和用量规则。

### 周礼盒

| 章数 | 礼盒内容 |
|---|---|
| 4 章 | 一件纪念品，每四周有一次改成一件行囊新东西 |
| 6 章 | 再多一件纪念品或一张旧明信片 |

礼盒有开箱动画，内容来自内置清单，不重复，集齐后换成重游线索。

### 记忆簿

回应、学会的事和特别的日子都写进记忆簿，写信时优先引用。这是最核心的长期资产。

每条兑现情节带一句它自己的心得，生成信时保存。M1 没有记忆簿页面，档案里显示最近学会的 5 条。

M2 记忆簿分为“你说过的话”“它学会的事”“特别的日子”，各类按时间倒序，可以回看相关信和回应的来处。特别的日子先记孵化日、第一封旅行信、第 100 个陪伴日；这些纪念日不依赖里程，用量翻倍不会改变记录。新国家仍记在护照，不在这一步另记纪念日。已有存档补齐纪念日，只存引用，不补发奖励。界面按当前语言读取信里的双语快照，玩家起的名字保留原文。

### 用量事件

用量事件只增加陪伴表现，不带额外奖励，不改变稀有度、掉落、保底、习惯、兑现、形态或陪伴日。歇脚明信片沿用已实现的独立规则。

| 触发 | 反应 |
|---|---|
| 当天最终里程超过此前最近 14 个活跃日里程中位数的 2 倍 | 走得很远，端来一杯茶：“今天辛苦了” |
| 没有用量的一天 | 当天打开过主窗口，日结后写一张歇脚明信片，次日送达；读到时记陪伴日 |
| 本地时间 23:00–05:00 仍观察到新增用量 | 戴上睡帽陪你，每个本地周一开始的周最多一次 |
| 本旅程第一次用某个工具 | 首航，得一张船票，每个归一化工具 ID 只发一次 |

茶只在日结读到当天最终用量后判断，当天中途不作永久决定；基准只取此前最近 14 个最终里程大于零的已结算活跃日，不包含当天，偶数样本的中位数取中间两项的平均。少于 14 个有已知最终值的活跃日不触发；回溯样本时遇到没有最终值的旧记录就不触发，不跳过它改用更早的样本；跨天扫描读到最终值后才可纳入，不设固定里程下限。因此全部用量等比翻倍时事件结果相同。旅程里程保持只增不减，但茶事件和后续基准使用日结读到的最终值，最终值下修也不会保留中途的强度判断。

茶和首航各在下一封新生成的旅行信中加一句，完整中英文在生成时写进正文快照。没有旅行信时保留到下一封，不单独发信或通知；同类待写事件合并，最多一句；有多个首航时按首航日期、归一化工具 ID 稳定选一个来写，每个工具仍各有船票。文字按旅程种子选择，每类至少四条原创双语文案，内容包更新不改旧信，切换语言读取保存的对应语言正文。

深夜事件只使用应用运行期间两次成功扫描间观察到的当日总 token 增量（含缓存读取和推理）及观察时间，不用里程燃料代替实际工作用量。每次启动、存档恢复或导入、唤醒后的首次扫描仅建立基线；应用没有运行或处于睡眠时不补发。跨午夜后只看新日用量，事件日期归观察时的本地日，周限额按该日所属的周一计算，不把凌晨归给前一天。睡帽持续到这一夜的本地 05:00，邮局与陪伴窗口可见，只是绘制覆盖层，不修改存档角色外观。

工具指 tokscale 工具 ID，沿用仓库的工具归一化规则，模型与工具别名都不是新工具。首航从本旅程 tokscale 报告有 token、消息或费用的工具登记，包括没有产生里程的缓存读取活动，船票独立保存归一化 ID 和首航本地日期。旧存档启用时以已有日记录和旧信中出现过的工具作为基线，不为这些已有工具补发船票，也不补发旧日期的茶或深夜事件；补算中才首次出现、存档里此前没有的工具，仍按首次活动的本地日期登记船票。船票放在收藏的护照页下方，显示工具名和本地化首航日期，有空状态；不是纪念品，不进掉落、礼盒或架子。

## 旅途与信件

### 下一站怎么定

**下一站随机，玩家不选。** 先按距离分档抽取，再在档内抽城市：没去过的城市权重更高，也保留重游机会；符合本周心愿的城市再加权。选定后在刘海和旅途显示目的地和剩余距离。

### 信的结构

1. **它的话：** 允许虚构，优先引用记忆、习惯和连载。
2. **今日见闻：** 只放核实过的真实内容并附来源；没有就不写。
3. **行程单：** 用量、里程、与平时的比较、工具比例。
4. **回应：** 选项写入记忆簿。

| 信的类型 | 什么时候来 |
|---|---|
| 旅行信 | 有用量的一天，第二天 09:00 |
| 歇脚明信片 | 当天打开过主窗口且最终用量为零，日结后写，次日按设置的送信时间送达 |
| 重逢信 | 离开 3 天以上后回来 |
| 周日长信 | 周日按设置的送信时间送达，回顾本周周一到周六 |
| 记忆信 | 第 100 天、周年等特别的日子 |

### 长途日

一天经过多座城时，只为一座城写完整故事：当天到达的城市里最后一座有资料的。其余只盖路过章，所以用得多不会多收信。

当天没有到站时也照常写信：用途中或通用情节，掉落取当前所在城市的东西。

### 城市内容

**每座城建一次档，随应用或内容包发布。** 运行时只读本地资料，不搜索、不调模型，不消耗 token。

- **内容：** 每城约 2 个景点、2 种美食，每条保留来源。真实资料和虚构情节分开存放，都有简体中文和英文。
- **建档：** 开发时用带搜索的模型从当地文旅部门、景区或博物馆收集，再人工核对。
- **修订：** 勘误时发布新版，已寄出的信保留原样。
- **没有资料的城市：** 只写天气和 Wikipedia 地点介绍，不编造当地细节。

情节示例（来源待建档时核对）：

| 城市 | 景点与美食 | 可以发生的事 |
|---|---|---|
| 杭州 | 中国茶叶博物馆龙井馆区、龙井虾仁 | 上午看炒茶，晚饭才发现茶叶还能入菜 |
| 景德镇 | 陶阳里御窑博物馆、冷粉 | 试着拼复制瓷片；爱搭话时问出摊主加的那点橘子香 |
| 苏州 | 拙政园与谁同坐轩、三虾面 | 带速写本时，沿水边找能同时画下扇形亭和倒影的角度 |
| 泉州 | 蟳埔村簪花围、面线糊配油条 | 在村里认花，又学会把油条一半泡汤、一半留脆 |

**内容量是这个设计最大的风险。** 一年约 260 封信，要靠城市资料乘以习惯、工具和记忆才撑得住。M1 之前，内容比代码更值得投入。

外部内容和模型输出都是不可信输入；信件的对外请求只带城市名或坐标，不带用量和项目信息；日常运行不消耗云端 token。

## 收藏

**普通收获是当地风物，稀有收获来自一次特别的际遇。**

| 类别 | 规则 |
|---|---|
| 护照 | 国家印章；城市分三级：路过、停留、熟客（停留 3 次）|
| 行囊 | 可以带出门的东西，不消耗 |
| 纪念品 | 摆在邮局，永久保留；它偶尔拿起一件讲旧事。架子上有“全部”入口 |
| 手绘菜单 | 吃过的菜各留一张，有独立的菜单页 |
| 稀有物 | 都能通过普通旅行获得；连续 8 封没有稀有就保底 |
| 旅行线索 | 重复的纪念品积累成线索，攒够后解锁重游故事 |
| 邮友 | 奇遇里认识的原创角色，住进邮局，偶尔捎话。先从内置角色和介绍里随机，不做用户标签总结 |
| 船票 | 本旅程每个归一化工具首次使用时得一张，收藏护照页下方查看；旧档已有工具不补发 |

掉落由种子和信件序号决定，与用量无关。

**收集内容先内置一批：** 开发时可以借助 AI 生成草稿，人工筛选后存入内容库并随应用打包，运行时不生成。

### 足迹入口

旅途页展示最常去、最远和最难忘，规则见[详细规则](#我的足迹)。护照里的路过、停留、熟客是同一份数据的详细版。

## 数据

数据部分是严肃工具，不做游戏化，也不影响游戏。

### 看板

- **时间范围：** 今天、7 天、30 天、90 天、1 年、全部。7 天及以上和上一周期比较。
- **总览：** 总量、估算费用、计入里程、缓存命中、消息、活跃天数、连续天数、会话时长、峰值日、主力模型。
- **趋势：** 总量、里程、费用或消息，按工具堆叠；90 天内按天，更长按周，当天按小时。
- **活跃：** 一年的每日方格，以及时段和星期分布。
- **明细：** 按工具、按模型、token 构成和完整表格。
- **下钻：** 点一天、一个工具或一个模型，整个看板都跟着筛选。

### 额度

只在“数据 → 额度”面板里显示，刘海、浮窗和小部件都不显示。工具太多，也不是每种客户端都有额度。

- **有额度窗口：** 显示剩余比例和重置时间，低于 20% 时变成珊瑚色。
- **API 直连：** 按量计费，没有额度上限，显示“按量计费”和已用费用，不显示无穷或 100%。
- **读不到：** 显示未关联或失效，以及下一步操作。

额度只提示，不影响游戏。

### 关联账号

用户逐个工具关联：使用本机登录、粘贴密钥或网页授权。默认不读取任何其他应用的凭据。没关联的显示“未关联”，失效的显示原因和下一步操作。实现见[技术方案](technical.md#用户关联账号和额度规划)。

## 异步偶遇（有真实用户后）

偶遇必须有一个服务端，这就是 **Voyage Hub**。它是 Voyage 自己的服务，和 Token Monitor 的 Hub 没有关系。单人玩法不需要 Hub，连不上也完全不受影响。

- **脚印和问候：** 同一地点近期到访的旅人留下脚印，可以发预设问候。
- **访客：** 其他人的宠物偶尔来邮局做客，复制一件对方摆出来的纪念品作为上门礼物。原件不减少。
- **双签明信片：** 双方同意后拼成一张。

默认关闭、只用预设短语，遇不到人时不影响单人体验，不比较也不公开用量。

足迹和收藏涉及和别人互动，要防止随意改存档作弊：开启后存档绑定设备，定期把足迹和收藏同步到 Voyage Hub。接口草案见[技术方案](technical.md#voyage-hub异步偶遇规划)。

## 详细规则

括号里的数字是初值，集中放在配置里，跑两周后按实际调整。

### 一天的时间线

| 时间 | 发生什么 |
|---|---|
| 工作中 | 按用量增量前进；到站时更新位置和目的地 |
| 跨天后第一次扫描 | 结算前一天，生成信和掉落，判断茶与首航事件，补算错过的日子；深夜事件不补发 |
| 次日 09:00 | 信显示为新信，发通知；送信时间可在设置改 |
| 拆信 | 记陪伴日，盖早安章；检查形态和礼盒 |
| 回应或跳过 | 写入记忆簿，调整习惯，登记待兑现 |
| 带东西 | 记录明天旅途带的东西；不选时结算当晚随机抽一样 |

一天没有用量时不生成旅行信。只有用户当天实际打开过主窗口，且这一天结算后的最终用量为零，才写一张歇脚明信片，日期记为这一天。明信片与旅行信一样，按设置的送信时间在第二天送达，送达前不显示。早上打开时用量为零不写；当天后来有用量就只结算旅行信。扫描失败时不结算，下次成功时按日期顺序补算，只处理确实打开过的零用量日，每日最多一张；未打开的日期不补发，旧存档没有打开记录的日期也不补发。打开记录只存在本机。明信片和普通信都在读到时记阅读当天的陪伴日，同一天只记一次，不在打开或写信时记。重逢信仍在回来时立即送达；重逢日若最终为零用量，当天的明信片次日送达。

明信片和重逢信优先从记忆簿的回应和学会的事中引用一条双语内容完整、来源信已送达的记忆；没有合适记忆时用不带引用的完整正文。正文、引句、来源引用和物品说明在生成时保存双语快照，旧信不重写。信箱“全部”显示所有已送达的信和未读红点，“明信片”包含歇脚明信片；重逢信只在“全部”显示，引用可打开记忆簿及来源信，记忆簿也能回到引用它的新信。“翻开这段记忆”和“回看这封信”放在正文和署名之后；引句引用完整句子时不重复句末标点。明信片和重逢信不占显示编号，旅行信标题、信箱、收藏来源、兑现链接和记忆簿中的编号保持一致；内部信件 ID 和抽选种子仍沿用原规则。

### 周日长信和信箱分类

- **时间和范围：** 每周一封，周日按用户设置的送信时间送达，送达前不可见。一周按用户本地时间、周一开始；长信只回顾本周周一到周六这六个已结算日的最终数据，不包含周日当天。日结或扫描失败时等成功结算后再生成。
- **内容：** 正文包含六天的里程、按用量汇总的工具比例、与上一周同样六天相比的里程趋势，以及一件大事。上一周六天的数据不完整时不写趋势；上一周为零而这周有用量时写重新上路，不计算无穷大的百分比。零用量但打开过主窗口的一周有完整的歇脚文案。
- **一件大事：** 只从这六天已发生的事里，按“回应兑现 → 稀有纪念品 → 第一次到新国家 → 里程最长的一天”选一件；同级按日期、内部信件 ID 排序，最长一天同里程取较早日期。兑现必须有完整双语的学会内容，纪念品和国家也须有完整双语名称。选不到时用不引用大事的完整正文。
- **活动和补算：** 这六天既无用量，也未打开过主窗口时不写。App 长时间未运行，只处理最近已到的一个周日，不积压补发更早周；最近一周无活动也不退回旧周。旧存档升级时从下一个周日开始，包括周日当天升级也不补当周。
- **独立于养成：** 长信与周礼盒分别处理，不发奖励，不推进或重置掉落保底，不推进待兑现回应的窗口、不兑现回应，不改变习惯，也不消耗行囊。读到时按现有规则记阅读当天的陪伴日，同一天只记一次。
- **保存：** 正文和统计数据在生成时保存双语快照，切换语言读取对应快照，更新内容包不会重写旧信。开头和结尾用稳定种子选取。长信不占旅行信显示编号，所有编号引用保持一致。
- **分类：** 信箱按“全部、旅行信、明信片、长信”显示，仅列已送达的信。旅行信只含每日旅行信；明信片包含歇脚明信片；重逢信和航海日志放在“全部”；首航只在旅行信里追加一句。每类有独立空状态。

### 下一站

到站时立刻抽取并保存，已保存的结果不再改变。

1. **排除：** 当前城市、最近 3 个停留城市、已下线城市。
2. **分档：** 以近 14 个活跃日的里程中位数 M 为基准（最小 300 km）：近途不超过 1×M，中途不超过 3×M，其余为远途。没有数据时 M 取 300 km。
3. **抽档：** 权重近途 5、中途 4、远途 1；某档没有城市就从其余档抽。
4. **抽城市：** 没去过 ×3，新国家再 ×2，符合本周心愿 ×3，有城市资料 ×2；再按城市的知名度档位乘 8、4、2、1，这样常去有名的地方，偶尔去小地方。
5. **随机数：** 由种子和已到站数决定，存档可复现。

第一站优先抽近途且有资料的城市，保证第一封信有内容。近途没有时取最近的有资料城市；都没有资料时取最近的城市。

### 习惯

每个习惯 0–100（初始 0），玩家只看到文字和进度条。

| 事件 | 变化 |
|---|---|
| 回应带该倾向 | +10 |
| 这封信的情节由带着的东西触发（每封信最多一次，不要求当天到站；是否触发由种子决定，与到了哪座城无关；兑现信不加）| +3 |
| 跳过回应 | 不变 |

**兑现：** 回应后登记一条待兑现。第一次回应后，下一封信必定兑现，保证第 3 封信前玩家能看到变化。之后的回应由种子决定在 1 到 3 封信内到期；积压时依次来，每封信最多兑现一个。到期时优先用当地情节，其次用这句回应专属的后续，最后用通用模板。到期时机与用量和到了哪座城无关，否则用得多的人会更早看到变化。

### 形态和身份

形态只看陪伴日。进入旅人时结算身份，到老练和传奇时再结算一次：

| 身份 | 得分 |
|---|---|
| 联络员 | 爱搭话 |
| 速写家 | 爱观察 |
| 美食家 | 手绘菜单数 × 3 |
| 收藏家 | 纪念品数 × 2 |
| 探路者 | 国家数 × 4 |
| 老街坊 | 熟客城市数 × 10 |

取最高分；差距在 10% 以内时用种子随机。结算时写一封身份信，说明原因。

### 掉落

每封旅行信一件当地东西，每张明信片一件旧物。用量不参与。

| 稀有度 | 概率 |
|---|---|
| 普通 | 70% |
| 少见 | 25% |
| 稀有 | 5%，连续 8 封没有时保底 |

- 重复的纪念品转成该城的旅行线索；3 条线索解锁一个重游故事。
- 菜单来自情节，吃到才有，不进入概率。它和护照一样取决于去过哪，所以用得多的人可能收得更多；不要让它影响稀有度或习惯。到 M4 身份“美食家”按菜单数计分时要重新评估。
- 情节指定的奖励只替换当封的掉落，不额外多一件。
- 明信片使用独立的通用旧物池，采用上表概率，与旅行信共享连续未出稀有的计数；连续 8 封旅行信或明信片未出稀有后，下一封此类信必出稀有。重逢礼使用独立普通礼物池，固定一件，不推进也不重置这个保底。
- 明信片和重逢信均不推进待兑现回应的 1–3 封窗口，不兑现新行为，也不消耗当天行囊或增加习惯；下一封旅行信仍按原定窗口兑现。
- 旧物和重逢礼优先给未收藏的一件，池内该稀有度全部收藏后，仍在信里记一件，重复收藏按既有规则转为信件所在城市的线索。三个物品池和礼盒物品互不混入。
- 掉落结果写在信里，重算不会改变；明信片和重逢信同时保存物品的双语名称与说明。种子、日期和内部信件 ID 决定抽选，按日期和内部 ID 幂等记账。

### 周章和礼盒

- **一周：** 周一到周日，按用户本地时间。
- **盖章：** 每个陪伴日一个。
- **礼盒：** 第 4 章和第 6 章各开一次，当周可领，过周也保留到下次打开。
- **内容：** 按内置清单顺序不重复发放，礼盒专属的纪念品不进普通掉落。孵化后第 4、8、12… 周的第一个礼盒发行囊新东西，行囊都有了就发纪念品。清单发完后改发旅行线索。
- **架子：** 先能摆 4 件，满了要先收起一件。

### 本周心愿

- **写入：** 邮局每周一句，最多 40 个字符（组合表情算一个）；可随时改，也可以不写或清空。下一次抽站生效，已经抽好的下一站不改变。周一按用户本地时间清空，不算失败。
- **解析：** 只在写入时先按当前语言的内容关键词匹配标签；macOS 26 及以上且本机模型可用时再补选标签，输出经过已有标签表校验。模型不可用、3 秒超时或失败时保留关键词结果。标签和解析时间随心愿保存，之后抽站和选情节只读保存的标签，切换语言也不重新解析。
- **结果：** 关联到标签时给下一次抽站加权，并按现有优先级选带该标签的情节；关联不到就随机，下一封新生成的旅行信说明一次，说明的中英文正文保存在信件快照里。
- **边界：** 原文按纯文本保存和展示，不翻译，只存在本机，不上传，也不会被当作指令执行。心愿不改变稀有度、掉落和保底、习惯、形态或用量规则。

### 我的足迹

三项都直接查旅程和记忆数据，不需要模型。

| 项目 | 规则 | 没有数据时 |
|---|---|---|
| 最常去 | 停留次数最多，同分取最近 | 显示家乡 |
| 最远 | 离家乡直线距离最远 | 显示“还没出远门” |
| 最难忘 | 记忆簿条目最多的城市，同分取最近 | 显示“还在攒故事” |

停留按已结算的每日旅行信所选的故事城市计一次；同一天只盖路过章的其他城市、途中未到站的旅行信，以及明信片、重逢信和长信都不增加停留次数。同分先比较旅行日期，再比较内部信件 ID。最远包含旅程路线中的路过城市，以家乡到该城市的大圆距离计算；距离相同取最近到达的城市。

最难忘统计记忆簿三类条目：你说过的话、它学会的事和有信件位置的特别日子；未送达信件引用的条目暂不计入。条目数相同，取最近一条记忆的日期，再取内部信件 ID，仍相同按城市 ID 固定排序。没有可关联城市的条目不参与城市排名。城市别名归并到同一城市，退役城市照常参与；内容包不认识的城市仍可参与次数排名并显示占位名称，但未知坐标不参与距离比较，家乡坐标未知时最远使用空状态。

三项每次直接计算，不写存档、不保存新统计字段，也不调用模型；点击护照入口查看已有护照。

### 通知

| 通知 | 默认 | 规则 |
|---|---|---|
| 早间来信 | 开 | 有新信时发，每天最多一条；正文取信的第一句 |
| 到达新国家 | 关 | 工作时间不打断，默认关闭 |

所有通知都用当前语言，不写内疚文案；系统未授权时不反复询问。

## 多语言

**界面和信件都是多语言。** 首批简体中文（`zh-Hans`）和英文（`en`），之后可加繁体、日语等。

| 内容 | 怎么处理 |
|---|---|
| 界面文字 | 全部走本地化资源，代码里不写死 |
| 信件、回应、物品、邮友 | 内容包里每条都有各语言版本，翻译要改写语气，不是逐字翻译 |
| 城市和国家名 | 城市资料带各语言名称；国家存 ISO 代码，名称放在内容文件里，不用系统区域的写法 |
| 地点介绍 | 按语言读对应语言的 Wikipedia，没有就不显示 |
| 天气 | 保存天气代码和温度，显示时翻译 |
| 玩家写的字 | 宠物名和心愿保持原文，不翻译 |
| 单位 | 中文用万和亿，英文用 K、M、B；里程都用 km，费用都用美元 |
| 日期 | 按系统区域显示 |

规则：

- **语言选择：** 默认跟随系统，设置里可以改；不支持的系统语言退回英文。
- **切换语言：** 旧信也切换到新语言。信在生成时保存所有可用语言的正文，所以内容包更新不会改变旧信。M0 留下的信按模板渲染两种语言，它们存的天气文字不再显示。
- **缺翻译：** 按所选语言 → 英文 → 简体中文回退。简体中文和英文必须完整，校验不通过不能发布。
- **排版：** 英文通常更长，按钮和卡片不能写死宽度，每个界面都要用两种语言检查。
- **字体：** 首批继续用 Fusion Pixel；加繁体或日语时要换对应字形。

## 城市

城市由数据文件定义，不写在代码里。覆盖全球约 7000 座（Natural Earth，公共领域）。

### 加一座城

1. 加一条城市数据：ID、坐标、国家、大洲、标签、各语言名称。
2. 可选：加城市资料和情节。没有资料也能到达，只写天气和地点介绍。
3. 运行校验。
4. 随应用或内容包发布。

地图位置由坐标算出，下一站和护照自动包含新城市。

### 规则

- **ID 永不复用：** 用稳定的英文 ID。改名只改显示名。
- **只下线不删除：** 不再抽取，但旧信、足迹和护照照常显示。
- **未知城市不崩溃：** 存档里有当前内容包不认识的城市时，显示占位名称，并继续旅行。
- **不改历史：** 新城市只影响以后的抽站，不改变已保存的路线和信。
- **标签：** 用统一标签表，比如 `coast`、`mountain`、`food`，供心愿和情节使用。
- **资料等级：** 每座城标记只有基本信息、有资料或有完整情节，界面不用显示，抽站时参考。

### 怎么发布

| 方式 | 说明 | 阶段 |
|---|---|---|
| 随应用打包 | 最基础的方式，离线可用 | M1 |
| 在线内容包 | 不发新版也能加城市和故事，下载后校验签名 | 公开发布前 |

## 发布计划

### 三个阶段

| 阶段 | 做什么 | 进入下一阶段的条件 |
|---|---|---|
| **本地测试** | 自用和身边几个人试用，ad-hoc 签名 | M1 跑满两周；第 3 封信时说得出它学会了什么；存档没丢过 |
| **小范围测试** | 约 20–50 人，正式签名和公证，能自动更新 | 第 30 天还有人每周打开；数据和额度没有严重错误 |

### 公开发布清单

- **名字：** 定正式名，查重名和商标，确定 Bundle ID 和域名。
- **分发：** 用 Developer ID 签名和公证，官网分发。应用要读其他工具的日志和运行 tokscale，大概率不适合 App Store 沙盒，届时再确认。
- **内置工具：** tokscale 一起签名；决定是否支持 Intel。
- **更新：** 自动更新，并能单独更新内容包。
- **隐私政策：** 写清本机读什么、什么会联网、额度凭据怎么处理、Hub 上传什么。
- **第三方许可：** tokscale、Fusion Pixel、Natural Earth；Wikipedia 文字的署名和相同方式共享要求。
- **接口条款：** 确认 Open-Meteo 的免费额度和商用条件；额度接口多为非公开接口，要评估条款和失效影响。
- **内容：** 简体中文和英文完整，城市资料逐条核对来源；严肃和敏感地区的路线策略。
- **稳定性：** 存档迁移测试、存档备份和导入、异常提示。

公开发布不等于偶遇上线。偶遇需要 Hub，可以晚于首发。

## 世界观与角色

世界邮局的邮路断了。你接手了家乡一间快倒闭的小邮局，门口捡到一颗蛋，孵出来的小信使成了唯一的员工。它每到一地，就把那里的东西带回来，顺便接上一段邮路。

| 角色 | 形象 |
|---|---|
| 阿鸽 | 戴邮差帽的信鸽 |
| 壳壳 | 背金币壳的蜗牛 |
| 皮箱 | 会走路的行李箱 |
| 小笺 | 长了腿的信封 |

不使用青蛙形象，也不用“打包后出门、等它回家”的流程，以免整体接近《旅かえる》。

## 视觉：邮局与夜航

像素风。有深色（夜墨）和浅色（信纸）两套主题，设置里可选跟随系统。下面是深色的色值，含义在两套主题里都一样；浅色为了可读性可以用更深的版本。颜色都在 `Content/themes/` 里，按用途命名，刘海始终纯黑。

颜色各有固定含义：

| 夜墨 | `#1D1A39` | 深色背景、信纸文字 |

| 琥珀 | `#F4B63F` | 只表示里程和进度 |
| 邮政红 | `#E5533D` | 只表示新信 |
| 深海 | `#2B6C8F` | 海洋 |
| 陆地 | `#3F7F5F` | 地图陆地 |
| 薄荷 | `#7FD1C7` | 新地点、新国家 |
| 暮紫 | `#8E86B8` | 次要文字 |
| 蔷薇 | `#EFA0A8` | 只表示陪伴和习惯变化 |

## 衡量粘性

只在本机记录，不上传。目标是假设值，跑两周后校准。

| 指标 | 目标 |
|---|---|
| 工作日主动打开率 | ≥ 80% |
| 信送达 24 小时内拆开 | ≥ 80% |
| 回应率 | ≥ 50% |
| 第 30 天仍每周打开 ≥ 4 天 | 达到 |
| 早间仪式时长 | ≤ 3 分钟 |
| **护栏：日均燃料** | 不因游戏上升 |

## 设计依据

用 2025-09-25 至 2026-11-05 的真实用量校准：

| 事实 | 设计结论 |
|---|---|
| 407 天里活跃 228 天；连续活跃中位数 3 天，最长 13 天 | 不用连续打卡，改用不清零的周章 |
| 月里程从 396 km 到 35,153 km，相差约 89 倍 | 成长不能和 token 挂钩 |
| 自 8 月起的 97 天走过 64 座城（估算）；城市库 107 座 | 奖励按天发，城市要能重访 |
| 缓存命中率中位数约 98% | 不用命中率决定掉落 |
| Codex 占 88%，68% 的活跃日只用一种工具 | 工具比例只做展示和首航收集 |
| 用量集中在 9–20 点 | 09:00 送信，熬夜只当偶发事件 |
